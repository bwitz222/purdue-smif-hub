# Purdue SMIF website: super audit and do-or-die fix list

Audit date: November 16, 2026. Scope: the live site at www.purduesmif.org, the repository at commit `1128b84`, and the production Supabase project. Fixes are on branch `claude/relaxed-dirac-dgiw94`.

## Verdict

The site was in better shape than most student-org sites: server-rendered, clean on desktop accessibility, sound database row security, no secrets in the repository. It had four problems that cost it applicants, search traffic or credibility, and all four are fixed on this branch:

1. Eight member profiles told search engines not to index them.
2. The Apply button on every page opened an expired form.
3. The homepage contradicted the team page on headcount and team count.
4. A member removed from the roster still had a headshot, bio and LinkedIn link served from the site.

Seven items remain that need you: a login, a decision, or a production database change I did not make without your sign-off. They are in the second table.

## Smaller items, your call

- **Bios.** Nine members have no personal bio: Sohum Sharma, Cian Murray, Charlotte Liu, Emily Ryu, Anjali Muthyala, John Battaglino, Felipe Restrepo, Luke Ellis, Giorgina Ninassi. Their pages are now indexable and substantive, but a bio is what ranks for a name. Eleven have no headshot (those nine plus Aanya Verma and Larissa Adamic).
- **Name mismatch.** The roster says "Mikhail Bilokin"; his bio opens "Michael Bilokin". Pick one.
- **Twitter handle.** Every page declares `twitter:site` as `@PurdueSMIF`. The handle is not in the footer or the organization markup, and x.com returned 404 for it on November 16, 2026 (x.com often blocks automated checks, so treat this as unverified). If the fund does not own it, remove the tag.
- **Recruiting calendar.** Every event on `/recruiting` is in the past. Post spring dates when they exist.
- **Search Console.** After deploy, resubmit the sitemap and request indexing for the newly opened profiles.
- **Image weight.** Headshots are 900px wide in 340px slots, 1.4 MB across `/team`. `placements-2026.png` on `/about` is a 381 KB PNG. Smaller variants would help; neither blocks anything.
- **Meta descriptions.** `/apply` is 160 characters and `/performance` 157, against the site's own 155 limit.
- **Low-priority hardening.** HSTS lacks `includeSubDomains`. No `security.txt`. `GET /api/public/hooks/...` returns an HTML page with status 200 where a 404 or 405 is expected.

## What was checked and found sound

- **Crawler access.** All 10 user agents received HTTP 200 and the full 28,855-byte profile page. Cloudflare is not blocking search or AI crawlers.
- **Server rendering.** Names, bios, roles and links are in the HTML before any script runs.
- **Email scraping.** Cloudflare's email obfuscation replaces student addresses in the served HTML, and the structured data carries none. Profiles are open to crawlers while the addresses are not harvestable from the raw page.
- **Database.** Row-level security is on for all 13 public tables. Public roles can read only what the site displays. Contact messages are unreadable to the public roles. The Supabase security advisor returned only informational notices.
- **Webhooks.** An unauthenticated POST returned 401.
- **Secrets.** None in the repository or its history. `/.env` and `/.git/config` return 404.
- **Redirects and status codes.** HTTP to HTTPS, apex to www and trailing slashes all redirect once. Unknown URLs return a real 404 marked noindex.
- **Layout stability.** Cumulative layout shift at or under 0.03 on every live page.
- **Charts.** The performance charts draw; an empty chart in one screenshot was an animation frame.
